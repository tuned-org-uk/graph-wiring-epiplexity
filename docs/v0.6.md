# Epiplexity 0.6: production API and migration

## Release scope

Current patch release: **0.6.1**.

Version 0.6 adds three ways to obtain code-length estimates:

| Method | Input | Model component |
|---|---|---|
| `static` | Fitted adapter and data | Adapter-supplied description cost |
| `prequential` | Token counts and loss curve | Integrated loss minus final residual |
| `requential` | Teacher-to-student KL log | Token-weighted KL sum |

All methods return bits. Their assumptions differ; their units do not. A
candidate model description is not, by itself, an upper bound on the model
component of the MDL optimum. A valid two-part code can bound the optimal
**total** code within a compatible model class and compute bound.

The log estimators implement numerical estimates inspired by
[the reference implementation](https://github.com/shikaiqiu/epiplexity).
They do not prove that the input logs implement a decodable coding protocol.
Training FLOPs, scoring time, and parameter precision are different quantities.
Selecting from a finite set of measured candidates does not solve optimisation
over all time-bounded programs.

## Loss-curve estimate

```python
from epiplexity import PrequentialEstimator

result = PrequentialEstimator.estimate(
    tokens=[0, 2, 5], losses=[4, 2, 1], loss_unit="bits",
)
assert result.model_bits == 5.5
assert result.data_bits == 5.0
assert result.total_bits == 10.5
print(result.to_json(metadata={"seed": 3407, "dataset_digest": "example"}))
```

Losses must be means per **scored token**, not sums per batch. Cumulative
counts must start at zero and strictly increase. Include the initial loss;
the estimator does not extrapolate a missing prefix. Tokens exclude padding
and masked targets. Inputs must be finite and non-negative.

For losses in bits, the rule is:

$$
C = \sum_{i=1}^{m} (t_i-t_{i-1})\frac{L_{i-1}+L_i}{2},
\qquad D = t_m L_{\mathrm{ref}},\qquad M = C-D.
$$

The implementation integrates the loss differences directly. This avoids
subtracting two large totals when the model estimate is small.

`final_loss` sets the reference loss; it defaults to the last loss. It must
refer to the same target distribution and use the same units as `losses`.
The default input unit is `nats`; conversion divides by the natural logarithm
of two. A worsening curve can produce a negative model estimate. The result
keeps that value with `negative_model_bits`; model selection rejects it.
Logging frequency and repeated passes over data affect the interpretation.
This trapezoid estimate is not an exact online block code.

## KL-based estimate

```python
from epiplexity import RequentialEstimator

result = RequentialEstimator.estimate(
    kl_values=[0.5, 0.25, 0], token_counts=[4, 8, 3],
    final_loss=2, evaluation_tokens=7, loss_unit="bits",
)
assert result.model_bits == 4
assert result.data_bits == 14
```

Supply mean pre-update KL in the direction teacher to student, evaluated on
teacher-generated data. Each step has its own positive scored-token count.
The evaluation corpus size is independent of the student training counts.
The caller supplies the training schedule and any KL gating.

$$
M = \sum_i n_i\,\mathrm{KL}(P_i^{teacher}\Vert P_i^{student}),
\qquad D = n_{eval} L_{final}.
$$

These equations use bits. Nats are converted at the API boundary. `observation_count`
is the evaluation token count for this method, not the student training count.

Use `requential` with the keyword fields from its Python example. Use `-` for
standard input. Success writes one JSON object to stdout. Invalid input writes
an error to stderr and exits with status 2, with no partial result.

## Streaming fitted-model scores

```python
from epiplexity import EpiplexityEngine

# adapter implements TTimeProbabilisticModel; batches yields sized chunks.
engine = EpiplexityEngine.from_batches(
    adapter, batches, store_per_item=False,
    metadata={"seed": 3407, "model_digest": "supplied-by-caller"},
)
print(engine.to_json())
```

`from_batches` consumes inputs once and retains no input batches. Aggregate
mode uses memory proportional to the largest batch. Set `store_per_item=True`
to retain all scores; then `to_json(include_per_item=True)` includes them.
Requesting discarded scores raises `ValueError`.

Adapters can override `batch_log_prob` to return a one-dimensional array of
natural-log scores. The default calls `log_prob` for each item. The PyTorch
classifier uses one forward pass for equal-shaped inputs. GNN, transformer,
and ArrowSpace adapters currently use the scalar fallback.

In streaming mode, `raw_bits(batch)` must be additive. For formats with shared
headers or corpus-wide compression, pass a whole-corpus `raw_bits` override.
The existing constructor remains available, with `batch_size=1024` by default.
It retains `X`; use `from_batches` for bounded-memory operation.

An evaluation snapshots model cost, scores, raw size, and supplied metadata.
Later model or config changes do not alter that result. Per-item properties
return copies. This does not make shared model inference thread-safe; manage
the model's concurrency in the deployment layer.

## Valid comparisons

- `discrete`: finite log probability mass, at most zero.
- `conditional`: discrete targets with side information held fixed.
- `density`: continuous log density, which can be positive.

A Gaussian density is not a probability mass for a stored float. A discrete
encoding requires a declared quantisation scheme and bin probabilities or a
justified approximation. There is no automatic float32 compression verdict.
The ArrowSpace adapter therefore declares `density` and reports `NOT_COMPARABLE`.
It remains a wrapper around an external probability model; this release does
not supply a sparse Gaussian solver.

Classifier and GNN scores encode labels, but their legacy baselines count
input features and graphs. Transformer scores condition on the first token
and can truncate the suffix. Their default reports are also `NOT_COMPARABLE`.
For a matched conditional target code, supply `raw_bits` and explicitly set
`baseline_comparable=True`. This declaration is a caller assertion; it does
not repair an unmatched or truncated target.

The legacy `compression_ratio()` method still returns the arithmetic ratio
for existing callers. Use `engine.result.compression_ratio` or JSON output for
the checked ratio. Unavailable, zero-denominator, and density ratios are JSON
`null`, never NaN or Infinity. `STRUCTURAL` means that the declared comparable
code beats the supplied baseline; it is not a proof of MDL-optimal epiplexity.

## Selection with a measured budget

```python
from epiplexity import Candidate, CodingResult, pareto_frontier, select_under_budget

runs = [
    Candidate("small", CodingResult("static", 10, 90, 100),
              10, "training_flops", "corpus-a/test/labels-v1"),
    Candidate("medium", CodingResult("static", 20, 60, 100),
              20, "training_flops", "corpus-a/test/labels-v1"),
]
assert select_under_budget(runs, 20).name == "medium"
frontier = pareto_frontier(runs)
```

Supply measured compute, its unit and scope, and a comparison key identifying
dataset, split, encoding, conditioning, and scoring protocol. The selector
rejects mixed methods, score kinds, counts, units, or keys. It minimises total
code, not just residual loss. Ties prefer lower compute, then name. It returns
`None` when no candidate fits. Precision settings alone are not compute budgets.

## Result contract and native ports

The result is an immutable `CodingResult`. It contains method, score kind,
model bits, data bits, total bits, observation count, optional raw size,
baseline comparability, diagnostics, and a checked verdict. JSON adds library
version, schema version `1.0`, and caller-supplied metadata.

The packaged [JSON Schema](../epiplexity/schemas/result-v1.json) defines the wire
format. Supply model/data digests, config, seed, compute measurement and unit,
and input-log provenance in metadata. The library does not fabricate these.

For a low-level port, start with the pure arithmetic in `estimators.py`,
`results.py`, and `selection.py`. These modules do not call training frameworks
or a sparse solver. [Golden vectors](../epiplexity/tests/fixtures/coding-v1.json)
provide language-neutral inputs and expected outputs, with float64 tolerances
of 1e-12 relative and absolute. Preserve log bases, counts, signed estimates,
validation, tie rules, and JSON null semantics. Do not require bit-identical
results across BLAS libraries or hardware. Model inference remains an adapter
boundary; a later Rust or C implementation can share this result contract.

## Release checks

```sh
UV_PROJECT_ENVIRONMENT=.venv-code uv sync --extra dev
UV_PROJECT_ENVIRONMENT=.venv-code uv build
UV_PROJECT_ENVIRONMENT=.venv-code uv run --extra dev pytest
```

Tests cover estimator arithmetic, irregular intervals, invalid logs, streaming
equivalence, one-pass consumption, model snapshots, adapter semantics,
budget selection, CLI jobs, the JSON schema, and packaging. A lean-wheel smoke
test must run outside the source directory with only core dependencies.

Both build targets use explicit file inclusion rules. The wheel contains runtime
Python modules and the result schema. The source archive also contains build
metadata, the README, license, changelog, and this guide.
Tests and golden vectors stay in the Git repository and are excluded from both
archives, along with notebooks, research reports, plots, paper files, example
scripts, local environments, and caches. Run release checks from the Git checkout.
Archive-content tests check the actual built files.

Publish only the checked release files, since an unrestricted `uv publish` can
also select older archives left in `dist/`:

```sh
uv publish dist/epiplexity-0.6.1-py3-none-any.whl dist/epiplexity-0.6.1.tar.gz
```
